Optimizing for Almost Sorted Data: Sort Pushdown in Apache DataFusion (5 minute read)

Apache DataFusion now exploits sortedness automatically, even when data is only partially sorted or its ordering was never declared. The engine discovers a global sort order from per-file min/max statistics, deletes redundant sorts at plan time, and biases scan order toward the most-promising files, with dynamic filters driving row-group pruning at runtime. The payoff is ORDER BY ... LIMIT queries that skip the blocking full sort and full scan, cutting latency and peak memory on large tables.

Aurora DSQL: Scalable, Multi-Region OLTP (5 minute read)

Amazon's engineers detail Aurora DSQL, a distributed PostgreSQL-compatible OLTP database that disaggregates compute, transaction commit, and storage into independently scalable layers with active-active multi-region writes. The design leans on optimistic concurrency control and precise EC2 clock synchronization to guarantee strong consistency without a two-phase commit coordinator on the hot path. The bet is that decoupling the write path from storage lets a single database scale horizontally while surviving regional failure, a trade-off that swaps lock-based contention for commit-time conflict aborts.

PGSimCity - How PostgreSQL Works (1 minute read)

PGSimCity is an interactive, browser-based model of the PostgreSQL engine that renders the query lifecycle as a running city, walking through the parser, planner, buffer cache, WAL, and executor as connected systems rather than isolated concepts. The author frames it as an early, unreviewed prototype that likely contains inaccuracies, but it works as a mental map of how a page moves from disk to shared buffers to commit. It topped Hacker News at 625 points.

DuckDB Internals: Why is DuckDB Fast? (Part 2 Vectorized Execution) (5 minute read)

DuckDB's second internals post explains vectorized execution: instead of processing one row at a time, DuckDB pushes batches of values through each operator, keeping the CPU fed rather than stalling on memory waits and instruction dependencies. The payoff is concrete. The 2005 MonetDB/X100 benchmarks it cites clocked MySQL's row-at-a-time engine at 0.8 IPC and ~49 cycles per addition, versus ~2.2 cycles for the batched approach that DuckDB now builds on.

How MVCC and Transactions Work in RocksDB (5 minute read)

RocksDB implements MVCC on top of its LSM-tree, where writes never modify keys in-place and instead append new versions that compaction later garbage-collects. This post walks through the other half: how snapshots give each reader a consistent view of the data as it existed when the read began, letting readers and writers proceed concurrently without locking. It then builds up atomic updates and transactions on that foundation.

To Every Agent Its Own Database (5 minute read)

Joe Reis inverts the "make the warehouse agent-ready" approach, arguing that scaling shared analytical platforms with bigger clusters and faster semantic layers still assumes an agent is just a very fast analyst on a central plane. His working prototype gives each agent its own embedded engine using DuckDB, DuckLake, Quack, and Malloy, letting agents exchange data products directly. The open question he surfaces: what contracts govern analytical exchange once no single system owns the semantic and computational authority.

How Our Universal Content Processing Platform Riviera Evolved for AI and Beyond (5 minute read)

Dropbox opened Riviera, the content-processing platform that has powered its file previews for roughly a decade, to outside developers via API and MCP tools. What began as an internal preview service now handles transcoding, PDF flattening, and text extraction across Search, Replay, Sign, and Dash, producing the equivalent of 8 years of video daily. The write-up covers the architectural decisions that let a single preview service become shared infrastructure, and why AI document pipelines drove the external release.

Personalization is an infrastructure problem (5 minute read)

The author argues that most personalization failures are architecture problems, not quality problems: personalization is a ranking decision that has to weigh user intent, item quality, history, availability, and business priority for every request in milliseconds. The piece uses Vespa to show why the usual stack struggles, since the ranking layer is often the one place that cannot see all those signals together. Combining them at query time, while the user is still there, is the real bottleneck.

Simple and Fast Algorithm for Graph-based Filtered Approximate Nearest Neighbor Search (Full Version) (1 minute read)

This paper tackles filtered approximate nearest neighbor search, where a query pairs a vector with attribute constraints like category, color, or brand, and existing graph indexes stall on arbitrary attribute combinations they never saw at build time. The authors propose a graph-based algorithm that handles any attribute filter without precomputing per-filter indexes, and report faster search across extensive benchmarks. For teams running vector search behind faceted product catalogs, it targets the exact case where a plain ANN index and a metadata filter fight each other.

Kalypso: Relational LLM Serving (1 minute read)

This paper introduces relational LLM serving, an abstraction that makes an LLM serving engine aware of the semantic query plan instead of treating each call as an isolated request. The payoff is KV-cache reuse across pipelined operators: when intermediate tuples flow from one semantic operator to the next, their cached state is reused rather than recomputed. The authors' system, Kalypso, pairs this with a memory-aware scheduler that balances GPU pressure against pipeline progress and reports query completion speedups up to 4.57x over request-centric baselines.

If You Think You Can Do Real-World Text-to-SQL (5 minute read)

The author argues that benchmark scores like those on Spider and BIRD wildly overstate how well text-to-SQL works against real production databases, where schemas are sprawling and undocumented, column names are cryptic, and business questions are ambiguous. The post walks through why enterprise schemas with hundreds of joined tables, inconsistent data, and implicit domain rules break models that ace academic benchmarks. The takeaway for data teams is that the hard part is schema semantics and context, not SQL generation itself.

DataOrchestra: Learning to Orchestrate Per-Example Curation of Pretraining Data (1 minute read)

This paper introduces DataOrchestra, a framework that decides per-example how to process pretraining data, choosing to drop, keep, or clean each chunk and picking the specific rewrite operation and instruction rather than applying one fixed strategy across a whole corpus. Training models from 0.5B to 7B from scratch, the authors report stable average gains over individual processing methods across 11 benchmarks, plus lower processing compute since unnecessary cleaning steps get skipped. It also beat stronger baselines on math continued pretraining.

SINT-Flow: Schema Integration using Large Language Model Workflows (1 minute read)

SINT-Flow is a schema integration framework of five LLM-based operators that derive a unified global schema from disparate input tables, including denormalized ones that mix multiple entity types. Unlike prior approaches, it decomposes those tables into entity-specific relations automatically. On the new SINT-Bench benchmark, it hits F1 scores of 96% for entity-type detection, 85% for attribute detection, and 83% for schema mapping using GPT-5.2 or open-weight Qwen-3.6-27B.

TEmBed-T: A Multi-Dimensional Benchmark for Table-Level Embeddings (1 minute read)

This paper extends TEmBed, a testbed for tabular embeddings, into a multi-task benchmark for table-level embeddings across retrieval, data lake discovery, and table classification. The authors find that no single model wins across all tasks, arguing that table-level embedding quality cannot be reduced to retrieval performance alone. For teams building data lake discovery or table search, the takeaway is to benchmark against your actual downstream task rather than trusting a leaderboard tuned on retrieval.

Order in Desbordante: Techniques for Efficient Implementation of Order Dependency Discovery Algorithms (1 minute read)

This paper tackles the implementation side of order dependency discovery, reimplementing the FASTOD and ORDER algorithms in C++ inside Desbordante, the open-source data profiling tool. ODs assert that one set of columns is sorted according to another, which is useful for query optimization, data cleaning, and anomaly detection. The reimplementations run up to 3x faster on their own, and the authors' bottleneck-targeting techniques push that to 10x while cutting memory use by up to 2.9x.

Backfilling: the most underrated feature of a data pipeline (5 minute read)

Backfilling gets treated as a throwaway migration script written under pressure, then abandoned in a scripts/ folder to rot. The author argues both forms of backfill, historical ingestion and system-to-system migration, are the same problem and belong inside the production extract-raw-transform pipeline rather than one-off jobs. Running historical loads through the same tested stages as tomorrow's data cuts the time teams spend fighting their own pipeline.

Smart caching with CTE on Spark (5 minute read)

Caching in Spark speeds up repeated computations by holding intermediate results in memory, but this piece argues the win only materializes for medium-sized, frequently reused datasets. Tiny tables gain nothing, and tables too large for memory trigger disk spills or eviction that slow the job down. The practical guidance for CTEs and nested queries: cache only when reuse is guaranteed, and watch the Spark UI storage tab to confirm the cache is actually paying off.

Answering Conjunctive Queries with Aggregations under Updates (1 minute read)

This paper maps exactly how adding aggregations (SUM, COUNT, provenance, shortest paths) changes which conjunctive queries can be kept up to date under updates. Under arbitrary insertions and deletions, aggregation adds no cost. Under insert-only workloads it does: the maintainable boundary shrinks from free-connex to a narrower strong-connex class. The authors adapt the CROWN algorithm to match the bound, maintaining every strong-connex query in O(1) amortized time regardless of the semiring.

Impute On-Demand: Adaptive Correlated Time Series Imputation for Changing Environments (1 minute read)

This paper introduces AdaCTSi, an adaptive imputer for filling missing values in correlated IoT time series that adjusts to sensor failures, partial sensor subsets, and available compute at inference. It pairs a one-shot temporal convolutional network with a learned time-sensor index table and sparse spatial attention, cutting MAE by an average of 33.1% over the strongest baseline across five traffic, air quality, and trajectory datasets. A single trained model runs on commodity hardware down to MCUs, so edge deployments no longer need separate models per sensor configuration.

Causal-TS: A Python Library for Causal Discovery in High-Dimensional and Nonstationary Time Series (1 minute read)

Causal-TS is an open-source Python library for causal discovery in high-dimensional, nonstationary time series, bundling four native algorithms (CDNOTS, CDNOTS+, CEDAR, GRACE) plus GES, Granger, and LASSO-VAR wrappers over a shared GPU-accelerated conditional independence layer. A regime discovery pipeline detects structural breaks and runs discovery per regime, and optional DoWhy integration takes raw series through to causal effect estimates.

Because Lakekeeper pushes catalog changes directly to Kafka with no metadata scanning, the agent flags breaking downstream dependencies within seconds and posts recommendations to Slack.

Extending Desbordante with Probabilistic Functional Dependency Discovery Support (1 minute read)

Desbordante, the open-source C++ data profiling tool, added support for probabilistic functional dependency (pFD) discovery, a relaxation of functional dependencies designed to handle the dirty real-world data that rigid FDs and even approximate FDs miss. The paper implements and benchmarks the pFD discovery algorithm against an AFD counterpart on runtime and memory, and tests whether either algorithm's output can substitute for the other.
