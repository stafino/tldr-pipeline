PostgreSQL's MVCC Is Bad: So Is Everyone Else's (5 minute read)

PostgreSQL's MVCC gets blamed for table bloat, write amplification, the 32-bit transaction ID limit, and endless VACUUM babysitting, but this piece argues each cost traces to a deliberate design choice rather than a defect, reproduced live on a PostgreSQL 19 beta2 instance. The author reframes the critique around four questions every MVCC engine must answer, and shows that alternatives like MySQL, Oracle, and SQL Server just send the bill to a different place: the writer, tempdb, the cache, or the compactor.

Oasis: Hiding the Cost of Querying Parquet Files in the Datapath (1 minute read)

Oasis is a data-processing SmartNIC that offloads Parquet decoding into the network datapath as a custom hardware accelerator, integrated end-to-end with DuckDB. The authors target the fact that scans account for roughly half of query runtime in production warehouses, a cost that lakehouses worsen through per-query decoding of compressed formats. By overlapping decode with the rest of query execution, Oasis nearly doubles DuckDB throughput in the best case, a sign that decode cost is moving into specialized hardware as network bandwidth outpaces CPU.

Why Large Language Models Fail at Tabular Prediction (1 minute read)

This paper studies why frontier LLMs still lose to decades-old baselines on tabular prediction, testing five hypotheses in a pure single-pass inference regime with no tools or fine-tuning. Controlled experiments falsify the usual suspects (noise, CSV formatting, numeric tokenization, batch size), leaving dimensionality as the decisive factor: across 31 benchmark datasets, the LLM is the only method of nine whose accuracy degrades as dimensions grow. In 2D it predicts like a local distance-based model, but in higher dimensions no classical learner reproduces its behavior.

Six Dimensions of Benchmarking Time-Series Databases (1 minute read)

This paper introduces SciTSv2, a benchmarking framework that evaluates time-series databases across six workload dimensions: connection parallelism, batch ingestion, series regularity, multi-variate series, mixed workloads, and system metrics. Running it against InfluxDB, TimescaleDB, ClickHouse, and DataLayerTS, the authors show that each dimension surfaces architectural behavior that single-axis benchmarks miss, including regularity-dependent trade-offs and contention between concurrent reads and writes. Paired with fine-grained system metrics, it traces performance back to CPU, I/O, and disk-bandwidth bottlenecks, grounding storage-engine selection in workload-specific evidence.

RaG-Tree: Combining R-Tree and HNSW for Multi-Attribute Range Filtered Approximate Nearest Neighbor Search (1 minute read)

RaG-Tree is a new index for multi-attribute range-filtered approximate nearest neighbor search, the operation behind vector queries that also filter on structured attributes like price or date. It pairs an R-tree for range pruning with partition-aware HNSW graphs whose density adapts to each partition's local vector distribution, plus a cost-based search that skips unnecessary graph traversal. On three real-world datasets the authors report faster queries than existing baselines alongside lighter indexing and fast incremental updates.

A Unified Benchmark for Privacy-preserving Vector Search (1 minute read)

Privacy-preserving vector search schemes have never been comparable, since each paper published its own corpus, threat model, and hardware. This benchmark runs a Plaintext baseline plus four cryptographic backends (SAP, EMVP, BNTM, Tiptoe) over one workload and metric set, and finds they land on a Pareto frontier rather than a flat penalty. SAP matches Plaintext throughput, EMVP costs 4x for cryptographic indistinguishability, BNTM adds malicious-server verifiability at 22x latency, and Tiptoe hides cluster choice at 190x per query.

Join Indices for Search Engines: a Prunable Parallel Semijoin over Lucene Segments (1 minute read)

This paper ports Valduriez's relational join-index technique to Lucene's LSM-style segment storage, materializing an append-only ordinal-to-ordinal join column for each parent-child segment pair to avoid query-time key translation. Its parallel semijoin runs per parent segment with no global barrier and prunes at three levels, so it composes with arbitrary engine queries. A Solr prototype joining 1M products against 10M skus cut average query latency 5.4x versus Solr's built-in join, widening to 8.3x at concurrency of eight.

Token-Native Storage: Read and Write in your Agent's Language (1 minute read)

This paper argues for token-native storage: keep text as the model's BPE token IDs instead of UTF-8, since embedders, rerankers, and LLM agents already read in token IDs and pay to translate on every access. Packing r50k IDs as uint16 beats UTF-8 by 2.25x uncompressed and 3.30x with an entropy coder, and serving IDs directly skips re-tokenization for ~10-600x faster reads. The catch is standardization: sharing token IDs requires a common tokenizer, which doesn't yet hold across model families.
