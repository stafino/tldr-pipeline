PGSimCity - How PostgreSQL Works (1 minute read)

PGSimCity is an interactive, SimCity-style visual model of the PostgreSQL engine that walks through how a query moves from parser to planner to executor and how buffers, the WAL, and storage interact along the way. The author flags it as an early, unreviewed prototype that likely contains inaccuracies, and invites issues and pull requests to correct the model and its explanations.

We have proof automation now (1 minute read)

The author revisits why dependently-typed languages like Lean and Rocq stayed niche, pointing to proof effort that dwarfs implementation. He cites the seL4 project, which spent roughly 10x as long on proofs as on design and code and ended with more than 20x the lines of proof versus C, then argues that automation has finally made verifying real code like zstd tractable.

Durable Objects are Made for Agents (5 minute read)

The author makes the case that Cloudflare Durable Objects, which pair an on-demand V8 isolate with a per-object SQLite instance and ID-based request routing, map cleanly onto agent workloads that need per-session state and event-driven execution via alarms. The post covers where the primitive shines for building agents and where it falls short, drawing on several months of building almost exclusively on DOs.

Postgres LISTEN/NOTIFY Actually Scales (1 minute read)

The authors optimized Postgres LISTEN/NOTIFY-backed streams to sustain 60K writes per second on a single server with millisecond latency, refuting the widely cited claim that the feature does not scale. The bottleneck was the global exclusive lock Postgres takes during every NOTIFY, which capped a naive per-chunk trigger implementation at 2.9K writes per second before the redesign batched notifications to avoid it.

I Inspected My Take-Home Interview Project. It Was a Whole Operation (1 minute read)

A developer accepted a take-home assignment from a LinkedIn recruiter and found a malicious payload hidden in the project's `.git/hooks` directory, disguised behind a clean `requirements.txt` and a legitimate-looking FastAPI codebase. Running `tree -a` surfaced the operation that a casual clone-and-run would have executed silently, a reminder that git hooks fire on standard commands and warrant inspection before you touch an untrusted repo.

Measuring Component Performance with the Container Timing API (5 minute read)

The Container Timing API lets developers annotate a whole region of the DOM and receive performance entries as new contentful parts of it paint, filling the gap between page-level metrics like LCP and single-node Element Timing. Developed by Bloomberg and Igalia and currently in a Chrome origin trial, it targets the components that actually matter to users, such as a product card or quote panel, rather than whatever element happens to be largest.

Characterizing Metastable Faults and Failures (5 minute read)

This paper offers the first analytical causal account of metastable failures, the self-sustaining goodput collapse that persists via internal feedback loops like retries and queues even after the trigger disappears. It frames a metastable fault as a "sin of composition" between individually stable components wired into a destructive cycle and ties recovery to scheduling, though the author disputes its claim that metastable fault tolerance can be designed through local pairwise reasoning alone.

From Homegrown to Flink: Migrating a Stateful Ad Event Join at Scale (5 minute read)

Zalando's Ad Platform team replaced a 7-year-old homegrown in-memory stream join with Apache Flink to match sponsored-product interactions against their originating auctions within a 15-minute billing window. The migration halved infrastructure cost and eliminated in-memory state loss on deploys and rescales, which previously forced pod overprovisioning because the old app had no checkpointing and couldn't cleanly partition across both event streams.

How MVCC and Transactions Work in RocksDB (5 minute read)

This post explains how RocksDB layers multi-version concurrency control on top of its LSM-tree, where immutable memtables and SST files already keep multiple versions of every key so writers never modify data in-place. It walks through the missing half, showing how snapshots give readers a consistent point-in-time view, how compaction garbage-collects stale versions, and how atomic updates and transactions are built on those primitives.

Introduction to Data-Oriented Design [pdf] (1 minute read)

This paper introduces data-oriented design, an approach that structures code around how data is laid out in memory rather than around objects and their behavior. It walks through cache-friendly patterns like struct-of-arrays layouts and hot/cold data splitting, showing how organizing for access patterns cuts cache misses and speeds up tight loops in games and other performance-critical systems.

Going depthfirst: Achieving GitLab RCE via Two Ruby Memory Corruption Vulnerabilities (5 minute read)

depthfirst's automated analysis of Oj, a JSON parser with a large native C extension, surfaced two long-lived memory-corruption bugs (an out-of-bounds write and a heap-pointer disclosure) that had gone unnoticed for nearly five years. Chaining them yields remote code execution on a default GitLab install across CE and EE versions 15.2.0 through 19.0.1, a reminder that memory-safe Ruby often calls into unsafe C gems. GitLab has since patched.

Aurora DSQL: Scalable, Multi-Region OLTP (5 minute read)

This paper describes Amazon's Aurora DSQL, a distributed SQL database that disaggregates the transaction, journal, and storage layers to scale writes and reads independently while keeping PostgreSQL compatibility. It relies on optimistic concurrency control with a single commit-time conflict check, and provides strongly consistent active-active multi-region deployments backed by a quorum-replicated journal rather than synchronous cross-region locking.

Drizzle's `with` is not a JOIN: peeking at the SQL it actually generates (2 minute read)

Drizzle's relational queries API compiles `with` into neither a JOIN nor N+1 lazy loading, staying at a single SQL statement regardless of nesting depth. The author wired up a custom logger against drizzle-orm 0.41 on SQLite/libsql and found the related rows are pulled via correlated subqueries in the SELECT clause and serialized with `json_array` and `json_group_array`, which keeps query count at one and matters for latency-per-query backends like Cloudflare D1.

Benchmarking Opus 5 on SlopCodeBench (1 minute read)

SlopCodeBench reveals coding requirements incrementally across 17 checkpoints in three projects, scoring a strict pass only when new tests pass and no prior checkpoint regresses. Opus 5 led at 24% (4/17) versus 6% for Opus 4.8 and Sonnet 5, but wrote ~29,000 lines with 11.6x the slop-trigger density of human-reviewed code, evidence that frontier models still can't maintain a codebase without human steering.

Industrial Practice of LLM-Based Test Case Carving and Assertion Generation (Experience Paper) (1 minute read)

NL2Test generates executable API regression tests for microservices from a natural-language scenario plus a captured traffic trace, using LLMs for semantic interpretation and constrained synthesis while deterministic algorithms handle request filtering, dependency binding via value consistency, and assertion-path validation. Across 51 industrial scenarios it hit an 82.4% exact-match rate, and a 9-month production deployment generated 3,196 test cases with an 85.4% code adoption rate.

The startup's Postgres survival guide (1 minute read)

A Hatchet engineer distilled two years of production Postgres experience into a survival guide for startups, covering schema design, the query planner, bulk updates, autovacuum, and advanced tuning. The doc assumes SQL basics and leans on practical rules of thumb over formal normalization, noting that ORMs block many scaling optimizations unless you can drop to raw SQL via tools like Prisma TypedSQL or sqlc.

The Illusion of Secure LLM Code: Closing the Security Gap via Iterative Reprompting (1 minute read)

The authors tested authentication code from five AI coding assistants against NIST SP 800-63B using static analysis and penetration testing, and found that functional or "make it secure" prompts consistently omit brute-force protection, sound session management, and robust password handling. Even single-shot NIST context is structurally inadequate, so they argue only iterative reprompting that forces models into a self-auditing loop yields defense-in-depth, pushing enterprises toward continuous verification pipelines over one-shot prompt engineering.

Scriptc by Vercel: TypeScript-to-Native compiler, no JavaScript engine in binary (1 minute read)

Scriptc compiles ordinary TypeScript into self-contained native binaries with no Node, V8, or JavaScript engine linked in, producing executables like a 178KB fib binary with roughly 2ms startup and no code changes or annotations required. Code that can't compile statically either runs through an optional embedded QuickJS engine under `--dynamic` or fails with a specific error code and code frame, and a `scriptc coverage` command reports construct-by-construct what compiles.

Ruff v0.16.0 – Significant new updates – 413 default rules up from 59 (1 minute read)

Ruff v0.16.0 now enables 413 lint rules by default, up from 59, pulling in flake8-bugbear, pyupgrade, and RUF rules that catch syntax errors and immediate runtime bugs without any configuration. The release also stabilizes formatting for Python code blocks embedded in Markdown and Quarto files, and users who want the old behavior can revert with `select = ["E4", "E7", "E9", "F"]`.

How AST-grep Rewrote Tree-sitter in Rust and Made It 30% Faster (1 minute read)

ast-grep rewrote Tree-sitter's C core in Rust, with AI generating the code, producing a parser that runs 30% faster and an end-to-end ast-grep workload about 22% faster. The tradeoff is scope and memory: the new runtime drops WebAssembly language loading and incremental tree reuse to target AI agents that analyze full file snapshots, and uses roughly 8 MiB more RSS per run.

Show HN: Let's Seal – Let's Encrypt for document signing, free and self-hosted (1 minute read)

Let's Seal is an open-source, self-hosted system for cryptographically sealing any file, proving it is unaltered, existed by a certain date via Bitcoin-anchored OpenTimestamps, and was issued by a specific domain-verified certificate. Built on the Apache-2.0 SEAL standard with a free hosted app, CLI, and REST API, it aims to be the Let's Encrypt of document proof, replacing paid document seals with a free public-benefit alternative.

Self-contained highly-portable Python distributions (1 minute read)

python-build-standalone produces self-contained, highly-portable Python distributions that statically link or bundle their library dependencies and limit both CPU instructions and required shared libraries to run on any system for the target architecture. Downstream repackagers can recombine the shipped build artifacts to strip features like SQLite or OpenSSL and embed Python in a larger binary, which is how sister projects PyOxidizer and PyOxy build single-file interpreter executables.

Show HN: CheapSecurity – Lightweight, Self-Hosted CCTV for Linux SBCs (1 minute read)

It streams live MJPEG to a web dashboard, records with a pre-motion buffer, pushes Telegram and email alerts on motion, and handles retention cleanup by age or disk pressure, all under AGPLv3 with no cloud dependency.
