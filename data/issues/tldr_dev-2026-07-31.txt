The Economic Benefit of Refactoring (1 minute read)

Martin Fowler describes an experiment on a 150,000-line agent-built application whose data access layer had ballooned to a single 17,155-line Rust file with no deduplication or extracted functions. By replaying the same feature-change prompt against a fresh agent after each refactoring stage, he measures whether disciplined refactoring lowers the token cost of future edits, treating cleaner structure as an economic investment rather than aesthetics.

Postgres LISTEN/NOTIFY Actually Scales (1 minute read)

The authors optimized Postgres LISTEN/NOTIFY-backed streams to sustain 60K writes per second on a single server with millisecond latency, refuting the widely cited claim that the feature does not scale. The bottleneck was the global exclusive lock Postgres takes during every NOTIFY, which capped a naive per-chunk trigger implementation at 2.9K writes per second before the redesign batched notifications to avoid it.

Making Postgres queues scale (1 minute read)

DBOS shows how to scale Postgres-backed queues to 30K workflow executions per second across thousands of workers, arguing you don't need RabbitMQ or Redis to handle demanding queue workloads. The core fix is `FOR UPDATE SKIP LOCKED`, which lets each worker lock and dequeue distinct rows instead of contending over the same oldest workflows, lifting throughput past the ~100/sec ceiling naive polling hits.

Measuring Component Performance with the Container Timing API (5 minute read)

The Container Timing API lets developers annotate a whole region of the DOM and receive performance entries as new contentful parts of it paint, filling the gap between page-level metrics like LCP and single-node Element Timing. Developed by Bloomberg and Igalia and currently in a Chrome origin trial, it targets the components that actually matter to users, such as a product card or quote panel, rather than whatever element happens to be largest.

More Tailscale tricks for your jailbroken Kindle (1 minute read)

“Stateful systems are incredibly hard to build”: How Perplexity thinks about AI agent sandboxes (5 minute read)

Perplexity launched SPACE, the sandbox platform under its Computer agent product, built on Firecracker microVMs and Kubernetes but with the real engineering going into a control plane that pauses, resumes, and forks agent sessions running for days or weeks across millions of sandboxes. The team leaned on Btrfs, the copy-on-write filesystem, to make snapshots and forks cheap metadata operations rather than full copies, treating state management rather than isolation as the hard problem at scale.

From Homegrown to Flink: Migrating a Stateful Ad Event Join at Scale (5 minute read)

Zalando's Ad Platform team replaced a 7-year-old homegrown in-memory stream join with Apache Flink to match sponsored-product interactions against their originating auctions within a 15-minute billing window. The migration halved infrastructure cost and eliminated in-memory state loss on deploys and rescales, which previously forced pod overprovisioning because the old app had no checkpointing and couldn't cleanly partition across both event streams.

New research: The Core Web Vitals thresholds you trust might be wrong for your site (5 minute read)

How ChatGPT Optimizes its Agent Loop: Harness, API, and Inference (5 minute read)

Drawing on interviews with the OpenAI engineers behind Codex and ChatGPT Work, this walkthrough traces an agent request through three layers and the efficiency tricks at each: persistent WebSockets, stable prompt prefixes, and Code Mode in the harness; delta-only tokenization and parallel safety checks in the API. The inference layer covers cache-aware routing, KV cache management, speculative decoding, and splitting prefill from decode to cut cost per successful task.

How MVCC and Transactions Work in RocksDB (5 minute read)

This post explains how RocksDB layers multi-version concurrency control on top of its LSM-tree, where immutable memtables and SST files already keep multiple versions of every key so writers never modify data in-place. It walks through the missing half, showing how snapshots give readers a consistent point-in-time view, how compaction garbage-collects stale versions, and how atomic updates and transactions are built on those primitives.

Going depthfirst: Achieving GitLab RCE via Two Ruby Memory Corruption Vulnerabilities (5 minute read)

depthfirst's automated analysis of Oj, a JSON parser with a large native C extension, surfaced two long-lived memory-corruption bugs (an out-of-bounds write and a heap-pointer disclosure) that had gone unnoticed for nearly five years. Chaining them yields remote code execution on a default GitLab install across CE and EE versions 15.2.0 through 19.0.1, a reminder that memory-safe Ruby often calls into unsafe C gems. GitLab has since patched.

GitHub is the wrong shape for this new world (5 minute read)

The author argues that GitHub's paradigm is the wrong shape for a world where anyone across a company can generate code, turning long-standing bottlenecks in source control, CI/CD, review, and deployment into company-wide pain rather than an engineering-team problem. The piece contends that bending human-centric collaboration tools into this new velocity is a mistake, and that it raises unanswered questions about code ownership, trust, and review that current infrastructure primitives cannot answer.

The session you cannot take with you (1 minute read)

The authors argue that inference APIs are drifting away from portable sessions, returning provider-bound state like encrypted reasoning tokens, compacted context, and server-keyed conversation IDs that the transcript on your machine can no longer fully capture. Their portability test is modest: not identical next tokens across models, but a transcript complete enough that another capable model could understand what happened and take over.

Shipping an MCP test agent: The boring parts nobody demos (3 minute read)

The author built an unattended five-agent test pipeline over MCP and argues the runbook, not the architecture, decides whether an agentic pipeline ships or stalls. The costliest failure mode is composition faults, where one agent's correct output is misread by the next, and he insists on answering the boring operational questions first: who owns the ticket an agent opens at 3 a.m. and what cleans up the draft tickets a stuck run leaves behind.

You don't have to be smart if you can think clearly (2 minute read)

The author argues the key engineering skill isn't raw speed of insight but the ability to think clearly at any pace, drawing a line between "smart" engineers who intuit solutions instantly and "strong" engineers who methodically grind when intuition fails. His method is to anchor on invariants, the assumptions that can't be false, and use them as solid ground to test the shakier ones when a problem won't yield to a flash of insight.

Why don't people use formal methods? (2019) (1 minute read)

Hillel Wayne argues that formal methods are unused less because they are too expensive and more because of a fragmented, tiny community, inconsistent terminology, and tooling that never made the leap from academic proof to everyday engineering. He separates code verification, design verification, and their specification counterparts to show that even high-assurance domains like medical devices and aircraft mostly skip full verification, and points to newer lightweight tools as the path to broader adoption.

Why more context can make your coding agents worse (3 minute read)

Feeding a coding agent more context often degrades its output, since it weighs stale decisions, reversed comment threads, and unrelated requirements as if they still apply. The author argues the fix is relevance over volume: a knowledge graph that scopes each task to the requirements, current decisions, and constraints that actually hold, so the agent reasons over the right slice instead of everything ever written down.

Critical Rails Flaw Could Let Unauthenticated Attackers Read Server Files via Image Uploads (1 minute read)

Rails patched CVE-2026-66066, a critical (CVSS 9.5) Active Storage flaw that lets unauthenticated attackers read arbitrary server files through crafted image uploads, exposing secret_key_base, database passwords, and cloud credentials that can escalate to remote code execution. Only apps using libvips for image processing on Rails 7.0 through 8.1.3 are affected, and operators should upgrade to 7.2.3.2, 8.0.5.1, or 8.1.3.1 and rotate every readable secret.

Two Compromised joyfill npm Packages Run RAT When Imported Into Node.js (1 minute read)

Two npm packages in the @joyfill namespace, layouts and components, were compromised in beta releases to deliver a remote access trojan tied to the DEV#POPPER malware family. The implant runs at import time when Node.js loads the CommonJS entry point, and pulls its encrypted payload through Tron, Aptos, and BNB Smart Chain transactions so operators can swap malware without publishing a new version.

GCC steering committee announces AI policy (1 minute read)

The GCC steering committee adopted a policy that declines any legally significant contribution containing or derived from LLM-generated content, using the GNU Project's threshold of roughly 15 lines of code or text. The rules still permit LLMs for research, bug discovery, and patch review, and allow maintainers to accept AI-generated test cases, with the committee expecting to revisit the policy periodically.

New Gitea RCE Lets Repository Writers Plant a Git Hook to Run Shell Commands (1 minute read)

Gitea patched a critical remote code execution flaw (CVE-2026-60004, CVSS 9.8) that lets any user with repository write access plant a Git hook and run shell commands as the service account. Because default installs leave registration open, an outside visitor can self-register and exploit unpatched servers with no prior credentials; the fix is upgrading to 1.27.1, and public PoC code is already circulating.
