KindaRails2Shell threatens Ruby on Rails apps (CVE-2026-66066) (1 minute read)

Researchers disclosed KindaRails2Shell (CVE-2026-66066), a critical Active Storage flaw that lets an unauthenticated attacker upload a booby-trapped image and read arbitrary files off a Rails server, exposing secret_key_base and often a path to remote code execution. It hits default vips-processor setups since Rails 7, so patch to Active Storage 7.2.3.2, 8.0.5.1, or 8.1.3.1 wherever a feature serves back processed image variants.

Smaller, faster, safer: running Kimi and GLM at scale (1 minute read)

Cloudflare's Workers AI team detailed three techniques for serving Moonshot's Kimi K-series and Z.ai's GLM models efficiently on shared H200 GPUs: quantizing the KV cache to FP8, compressing model weights, and protecting the shared cache. FP8 KV caching doubles resident context on Kimi K2.6 from roughly 686,000 to 1.37 million tokens with no accuracy loss, packing more concurrent requests per GPU to cut per-customer cost. All benchmarks run on the open-source SGLang serving framework.

Geography is the latency floor you can't move (3 minute read)

The author measured round-trip times from Tokyo to AWS regions worldwide and found a hard latency floor set by physics: 5ms locally, 166ms to US East, 373ms to Cape Town, a 70x spread that no model optimization can touch. Because the US round trip alone consumed 55–92% of the translation deadline, the biggest win came from placement, not code. Moving the inference server from the US to Tokyo cut ~160ms, more than every quantization and GPU tweak combined.

Launches & Tools

Your agent needs a computer, not a container — introducing @cloudflare/computer (1 minute read)

Cloudflare released an early preview of @cloudflare/computer, an agent runtime that gives each agent its own computer while the platform decides whether the code runs in an isolate, a container sandbox, or a browser. The pitch is scale: Cloudflare argues there isn't enough compute anywhere to give hundreds of millions of concurrent agents their own container, so it leans on isolates that spin up fast, hibernate when idle, and store the agent's state.

Cloudflare Workers and Containers now support inbound TCP connections and gRPC (1 minute read)

Cloudflare added inbound TCP and gRPC support to Workers and Containers, introducing a `connect(socket)` handler that accepts sockets from Spectrum and can route them to other Workers, Durable Objects, or containerized gRPC servers. Workers can now serve unary and server-streaming gRPC APIs via gRPC-web with automatic conversion, and Containers get full-duplex bi-directional gRPC, all available in private beta.

Introducing the Billable Usage API: programmatic cost visibility for Cloudflare (1 minute read)

Cloudflare launched a Billable Usage API for self-serve accounts, exposing per-product usage and cost through a single endpoint covering Workers, R2, D1, Workers AI, Vectorize, Images, and Stream. Column names map to the FOCUS FinOps spec, so teams already ingesting cost data from other providers can pull Cloudflare spend into the same toolchain, though data currently refreshes only once daily.

Workers RPC now works across Python and JavaScript (1 minute read)

Cloudflare extended Workers RPC to work across Python and JavaScript, letting a Python Worker call methods on a TypeScript Worker (and vice versa) with no schemas, protobuf, or serialization glue. The system translates types across languages automatically, so teams can wire multi-language services together with a single Service binding and treat cross-language calls like ordinary promise- or future-returning function calls.
