Tailscale didn't stop the Hugging Face intrusion (1 minute read)

Tailscale published a post-mortem on the Hugging Face intrusion, in which an AI agent escaped its sandbox, reached root on a Kubernetes node, read a 136-key secret store, and used a stolen Tailscale credential to enroll 181 nodes onto the tailnet. No Tailscale vulnerability was involved, and the company argues the real failure was long-lived credentials sitting in a central vault that becomes the prize once a rogue agent moves at machine speed.

Veeam, Terraform MCP, Django Patch Critical Flaws, Led by CVSS 10.0 Cross-Tenant Bug (1 minute read)

HashiCorp, Veeam, and the Django Software Foundation patched 11 vulnerabilities, led by a CVSS 10.0 cross-tenant flaw in Terraform MCP Server that lets one user's Terraform token be reused for later users' requests over Streamable HTTP. Operators should update Terraform MCP Server to 1.1.0, Veeam Service Provider Console to 9.3.0.35057, and Django to 6.0.8 or 5.2.17; none of the CVEs is under active exploitation yet.

Solving the "Noisy Neighbor": How Sharded Architecture Protects Multi-Tenant Platforms (2 minute read)

Google Cloud engineers describe migrating a monolithic multi-tenant data pipeline to a sharded hub-and-spoke pattern, where a lightweight Dataflow "hub" routes by tenant ID into Pub/Sub buffers that feed isolated "spoke" pipelines. The design shrinks blast radius from 100% to a single tenant, replaces worst-case scaling with tiered resource allocation, and lets high-priority tenants run dedicated Dataflow jobs while smaller ones share pipelines to hold down cost.

SNS vs SQS vs Kinesis vs MSK vs EventBridge vs RabbitMQ: An Architect's Decision Matrix (3 minute read)

This post lays out a decision matrix for six AWS messaging services, arguing the expensive mistake is picking a queue when you needed a log, or the reverse, which is a rewrite rather than a config change. It maps each to a workload shape: Kinesis or MSK for per-key ordering and replay, EventBridge for content-based routing, SQS for a durable one-to-one buffer, SNS for fan-out, and Amazon MQ for lift-and-shift RabbitMQ.

Celld: Self-hosted, distributed Durable Objects (1 minute read)

Deno released celld, an open-source daemon that runs Cloudflare Workers and Durable Objects on your own machines, backing each object with its own SQLite database that replicates to an S3-compatible bucket you control. Nodes coordinate through object-storage compare-and-swap alone, with no control plane, consensus service, or failure detector, so applications shard by construction and idle cells hibernate to near-zero cost.
