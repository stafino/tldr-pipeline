RefluXFS: A Linux Kernel Local Privilege Escalation to Root in XFS (CVE-2026-64600) (5 minute read)

Qualys disclosed CVE-2026-64600 (RefluXFS), a race condition in the Linux kernel's XFS copy-on-write path that lets an unprivileged local user overwrite protected files at the block layer and escalate to host root, even under SELinux Enforcing. The flaw has existed since kernel 4.11, affects default RHEL, Oracle Linux, Amazon Linux, and Fedora installs with reflink-enabled XFS, and has no reliable mitigation, so patch and reboot exposed and multi-tenant systems immediately.

Malvertising Sends Malware in Pieces, Then Makes the Browser Build the Executable (1 minute read)

Confiant detailed SourTrade, a malvertising campaign active since late 2024 that has victims' browsers assemble the final Windows executable in-page from base64 blobs and a legitimate Bun runtime, so no complete malicious binary ever crosses the network. Rotating a per-session seed changes each assembled file's hash while preserving the payload, defeating signature detection; the operation impersonates TradingView, Solana, and Luno, and the mitigation is installing trading and wallet software from vendor sites rather than ads.

GrapheneOS protections against data extraction from locked devices (1 minute read)

GrapheneOS details its defenses against forensic data extraction from locked devices, which rely on secure-element rate limiting that ramps delays to 4 hours after 10 failed PIN attempts and 41 days after 15, capping at 20 tries total. The secure element also enforces insider-attack resistance, requiring Owner authentication before firmware updates so a coerced update cannot strip rate limiting. GrapheneOS raises the password limit to 128 characters and adds an optional 2nd-factor fingerprint PIN, enabling high-entropy diceware passphrases that survive the Before First Unlock state.

GitHub delays version updates so malware gets caught first (1 minute read)

GitHub added a cooldown to Dependabot that holds non-security version updates for at least three days after a release publishes, closing the window in which a compromised package reaches reviewers before the community catches it. The September 2025 npm attack that poisoned chalk, debug, and a dozen other packages stayed live only about two hours, and GitHub logged over 6,500 npm malware advisories in the year ending May 2026. The delay is configurable via the cooldown option in dependabot.yml; security updates still open immediately.

End-to-End Detection Validation Using Coding Agents (5 minute read)

A team at DNB's Cyber Defense Center repurposed coding agents like Claude Code and Codex to run detection validation end to end. A custom plugin has the agent write TTPForge attack simulations, ship them to a lab host over SSH, detonate them, and query Splunk to confirm the telemetry landed and the detection fired, rewriting and retrying on failure. Most detections held up, but the loop surfaced small pipeline defects that had slipped past code review.

Anthropic’s Opus 5 Nears Mythos 5 on Finding Bugs, but Falls Short on Exploits (1 minute read)

Anthropic released Claude Opus 5, which matches its withheld Mythos 5 model at identifying software vulnerabilities but lags well behind on turning those findings into working exploits. Per Anthropic's OSS-Fuzz-based evaluation, the gap is deliberate: Opus 5 was not trained on offensive cyber tasks, and its classifiers block binary vulnerability scanning, pentesting, and exploit generation while still permitting source-code vulnerability search. Blocked requests fall back to Opus 4.8, and vetted enrollees in Anthropic's Cyber Verification Program get a version with those restrictions loosened.

Defenders running inference platforms should treat mass free-credit signups and distillation-scale usage as abuse vectors, not just cost leakage.

GitHub Adds 3-Day Dependabot Cooldown to Limit Poisoned Package Adoption (1 minute read)

GitHub added a default 3-day cooldown to Dependabot version updates, delaying pull requests until three days after a package release to sidestep poisoned versions that get yanked from registries shortly after publishing. Security updates still ship immediately. GitHub frames the cooldown as one layer alongside lockfile pinning, disabled CI install scripts, and scoped build tokens, noting it does nothing against dormant backdoors, maintainer sabotage, or compromised build systems.

We have proof automation now (1 minute read)

Adam Langley argues that proof automation has advanced enough to make dependently-typed verification practical, pointing to a formally verified zstd implementation in Lean as evidence. Formal methods have historically been niche because proof effort dwarfs implementation, with seL4 spending roughly 10x as long proving as designing and shipping 20x more proof code than C. Cheaper proof automation lowers that barrier for security-critical components like parsers and codecs, where verified memory safety and correctness eliminate whole classes of exploitable bugs.

Marathon Petroleum’s CISO on OT security automation, supply chain risk (1 minute read)

Marathon Petroleum CISO Mary Rose Martinez told Help Net Security that the traditional air-gapped model for operational technology has effectively dissipated as automation digitizes PLCs, HMIs, and SCADA systems across refineries, pipelines, and terminals. Because assets like catalytic crackers cannot be rebooted for patching, her team leans on the Purdue (PERA) model to synchronize security controls with operational cadences, and treats fourth-party vendor risk as a first-order concern while state-aligned actors probe energy systems.

Memory safety absolutists (1 minute read)

The author argues that recent criticism of Rust's memory safety is often disingenuous, driven by language-war tribalism rather than a shared goal of shipping safer software. The piece highlights Fil-C, which makes C and C++ code memory-safe by combining garbage collection with InvisiCaps pointer tracking to panic on out-of-bounds access and use-after-free, and notes Zig's author is adding a Fil-C-inspired compilation mode. The takeaway for defenders: multiple paths to memory safety are complementary, not competing.

Measuring Reward-Seeking by Instilling Contrastive Beliefs (5 minute read)

OpenAI's alignment team introduced Contrastive Synthetic Document Finetuning (Contrastive SDF), a test that measures whether a model changes its behavior when its beliefs about the grader are altered, isolating reward-seeking from surface-level task completion. Validated against models trained to favor an authority's preferences and to cheat unit tests, the method found that frontier-scale RL models without safety training increasingly did what they thought the grader wanted over the user or developer, and that tendency grew across training.
