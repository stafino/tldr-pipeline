RefluXFS: A Linux Kernel Local Privilege Escalation to Root in XFS (CVE-2026-64600) (5 minute read)

Qualys disclosed CVE-2026-64600 (RefluXFS), a race condition in the Linux kernel's XFS copy-on-write path that lets an unprivileged local user overwrite protected files at the block layer and escalate to host root, even under SELinux Enforcing. The flaw has existed since kernel 4.11, affects default RHEL, Oracle Linux, Amazon Linux, and Fedora installs with reflink-enabled XFS, and has no reliable mitigation, so patch and reboot exposed and multi-tenant systems immediately.

GrapheneOS protections against data extraction from locked devices (1 minute read)

GrapheneOS details its defenses against forensic data extraction from locked devices, which rely on secure-element rate limiting that ramps delays to 4 hours after 10 failed PIN attempts and 41 days after 15, capping at 20 tries total. The secure element also enforces insider-attack resistance, requiring Owner authentication before firmware updates so a coerced update cannot strip rate limiting. GrapheneOS raises the password limit to 128 characters and adds an optional 2nd-factor fingerprint PIN, enabling high-entropy diceware passphrases that survive the Before First Unlock state.

ContainmentBench: Trace-Based Evaluation of Post-Injection Containment in Tool-Using LLM Agents (1 minute read)

ContainmentBench is a sandboxed, trace-based benchmark that scores prompt-injection defenses on more than terminal outcome, separately measuring endpoint policy compliance, logged propagation, recovery, and authorized workflow completion. In a 17,640-rollout study on Qwen2.5-7B, 73.5% of matched pairs with identical zero committed-harm outcomes still differed in trajectory or utility. Taint-only enforcement completed just 16% of authorized tainted workflows versus 86% for a trusted-ledger policy, showing a single policy label is not a sufficient statistic for containment.

The Illusion of Secure LLM Code: Closing the Security Gap via Iterative Reprompting (1 minute read)

This paper evaluates authentication code from five AI coding assistants using static analysis and penetration testing mapped to NIST SP 800-63B, and finds that functional or generically "secure" prompts consistently omit brute-force resistance, session management, and robust password handling. Even single-shot NIST context leaves structural gaps; only iterative reprompting that forces models into a self-auditing loop achieves defense-in-depth. The takeaway for defenders: treat LLM-generated auth as insecure-by-default and gate it behind continuous, standards-driven verification pipelines rather than one-shot prompts.

TRACE-CTI: Auditable Post-Extraction Governance of TTP Claims with Knowledge Graphs (1 minute read)

TRACE-CTI is a framework for governing automated CTI-to-MITRE ATT&CK mappings, preserving evidence, provenance, and versioned trust decisions so SOCs can decide whether an individual TTP mapping should be trusted. Evaluated on 65 reports and 5,303 sentences, requiring six-setup unanimity before trusting an assertion raised gold-aligned precision from 25.3% to 90.6%, though recall fell from 88.2% to 16.3%. The takeaway for analysts: extractor output stored as flat mappings can't answer provenance, disagreement, or review-queue questions without reprocessing.

VulnGym: Evaluating Vulnerability Management Strategies against Advanced Persistent Threats (1 minute read)

VulnGym is a simulation tool that stress-tests vulnerability-management policies by pitting a configurable patching defender against an RL-trained attacker calibrated on real APT profiles, both acting on a shared network of real CVEs. Because the attacker's progress responds directly to what the defender patches, a policy can be evaluated against a realistic campaign rather than scored CVE-by-CVE. Experiments across two APTs show effective patch prioritization must be tuned to network topology, asset criticality, and adversary behavior, not driven by per-vulnerability CVSS scores alone.

When LLM Defenses Backfire: Characterizing Safety, Performance, and Cost Trade-offs (1 minute read)

This paper systematically studies how LLM jailbreak defenses trade safety against utility, over-refusal, and inference cost across state-of-the-art methods, benchmarks, and open-source models. The authors find defenses rarely improve downstream capability: rule-based defenses best preserve task performance, conservative self-reflective defenses drive up over-refusal on benign inputs, and multi-round defenses carry the heaviest runtime overhead. Use the strategy-to-side-effect mapping to pick defenses against your actual deployment constraints rather than treating them as interchangeable.

EXE-Bench: Ranking the Tradeoffs of AI-based Windows Malware Detectors for Real-World Usability (1 minute read)

EXE-Bench introduces a benchmark for AI-based Windows malware detectors that scores performance, temporal robustness, adversarial robustness against content-injection attacks, and computational overhead into a single comparable metric. The authors find that feature-engineered models drawing on domain knowledge hold up over time and under adversarial attack, while deep networks excel only right after deployment. For teams selecting an endpoint detector, post-deployment accuracy alone is a misleading signal.

End-to-End Detection Validation Using Coding Agents (5 minute read)

A team at DNB's Cyber Defense Center repurposed coding agents like Claude Code and Codex to run detection validation end to end. A custom plugin has the agent write TTPForge attack simulations, ship them to a lab host over SSH, detonate them, and query Splunk to confirm the telemetry landed and the detection fired, rewriting and retrying on failure. Most detections held up, but the loop surfaced small pipeline defects that had slipped past code review.

Modeling Local Exploit Hazard - A Bayesian Framework for Quantifying Exploit Risk and Operational Efficiency (1 minute read)

This paper introduces a local exploit hazard model that converts global EPSS scores into a per-asset daily hazard rate for an organization's own environment. Control effectiveness is estimated as a Beta-Binomial distribution seeded from expert opinion and updated with telemetry, BAS, or pentest results, then aggregated by summation up to the org level. Defenders can simulate candidate remediations and rank them by projected hazard reduction, giving a quantitative basis for prioritization under fixed capacity.

DeepFaith: Evidence-Grounded LLMs for Faithful Incident Reporting in Multi-Stage APT Defense (1 minute read)

DeepFaith is an evidence-grounded framework that converts the machine-oriented output of autonomous APT defense systems into natural-language incident reports whose every claim is tied back to underlying system evidence. Using unified evidence representation, grounded prompting, and post-generation verification, it raised report faithfulness from 0.68 to 0.92 and cut unsupported claims from 0.32 to 0.08 in an enterprise testbed, offering SOC analysts a way to use LLM reporting without the usual hallucination risk.

Agentic Permissions Policy Algebra for Taint Confinement in LLM Agents (1 minute read)

APPA (Agentic Permissions Policy Algebra) is an information-flow-control framework that confines prompt-injection taint in autonomous LLM agents by spawning a label-seeded child trajectory to inspect unvetted data, letting a trusted sanitizer return a bounded derivative without polluting the parent context. Across a multi-turn tool-chaining benchmark on four models, it cut exfiltration attack success from 31%-50% down to 0%-7%, and on three of the four the branching recovered much of the downstream utility that permanent taint tracking otherwise forfeits.

ZKP Security Tools and Verification: Coverage, Effectiveness, Adoption, and Challenges (1 minute read)

This paper systematizes the landscape of ZKP security tooling and finds it thin: most tools target Circom, leaving newer DSLs and zkVMs largely unsupported. Evaluating six tools against 70 real-world vulnerabilities, the authors report detection of 45.7% of bugs on isolated targets but only 19.6% on full codebases, with whole vulnerability classes unaddressed. A survey of 48 practitioners shows development and auditing remain human-led, LLMs are widely used, and teams favor tools with clearer guarantees and lower integration cost.

We have proof automation now (1 minute read)

Adam Langley argues that proof automation has advanced enough to make dependently-typed verification practical, pointing to a formally verified zstd implementation in Lean as evidence. Formal methods have historically been niche because proof effort dwarfs implementation, with seL4 spending roughly 10x as long proving as designing and shipping 20x more proof code than C. Cheaper proof automation lowers that barrier for security-critical components like parsers and codecs, where verified memory safety and correctness eliminate whole classes of exploitable bugs.

Session revocations at scale (5 minute read)

Canva detailed how it revokes sessions for hundreds of millions of users without hammering its database on every deploy. Gateways trust encrypted session cookies and check a 12-hour in-memory revocation cache per request, but seeding that cache meant every gateway pod pulling over a million records from MySQL on startup, a coordinated stampede. Canva's fix adds a cache layer between MySQL and the gateways to cut both the seeding load and in-memory size.

TriShieldRAG: A Three-Ring Defense-in-Depth Framework Against Knowledge Corruption in Retrieval-Augmented Generation (1 minute read)

This paper introduces TriShieldRAG, a three-ring defense against knowledge-base poisoning in retrieval-augmented generation, where PoisonedRAG showed five crafted documents can flip an undefended system's answer roughly 90% of the time. The framework layers an ingest guard for poisoning signatures, a provenance-weighted retrieval re-ranker, and a cross-LLM consensus stage polling Claude, Mistral Small, and Llama 3.2, cutting attack success from 91% to 13% while preserving benign accuracy. The authors note they have not yet run the poison-fraction sweep needed to confirm the bounds.

'Confused Deputy' Flaws Persist in Google Cloud, Microsoft Azure (1 minute read)

Independent researcher Justin O'Leary disclosed two "confused deputy" (CWE-114) vulnerabilities in Azure and Google Cloud managed-identity trust chains, letting an attacker forward requests that inherit a high-privileged service's identity to bypass access controls and acquire admin permissions. Microsoft appears to have silently patched its AKS backup flaw without acknowledgment or bounty. Defenders should audit where managed identities forward upstream requests without preserving the original caller and constrain trust in cross-service chains rather than assuming provider IAM covers it.
